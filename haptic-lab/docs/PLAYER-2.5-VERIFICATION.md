# 音源の長さ判定の修正

2026年10月6日（日本時間）。2.5.0／build 7。

## 原因と変更

以前はYouTubeの通知から長さ・時刻を先に更新し、本編の動画IDや再生状態を確認する前に保存した振動の長さと比較していました。別の動画や読み込み中の通知でも「動画と解析した音源の長さが違う」「作り直してください」と表示する経路がありました。

本編のID、正の長さ、再生・一時停止・終了状態を確認してから時刻を反映します。不一致の間は振動を停止し、曲の長さ・時刻は上書きしません。再生中の同じ長さの不一致が1秒以上続いた場合だけ双方の時間を表示します。本編の長さが一致すれば通知を消し、振動を自動で再開します。許容差（1秒と解析時間の1.5%の大きい方）は維持しています。

[YouTube IFrame APIの仕様](https://developers.google.com/youtube/iframe_api_reference#getDuration)でも、メタデータが読み込まれるまで長さは0とされています。広告だったと断定する修正ではありません。

## 指定動画の実測

対象：[lkiV3U0GfGg](https://www.youtube.com/watch?v=lkiV3U0GfGg)。PC上のyt-dlpで同じ動画のM4Aを一時取得し、FFmpegで全体のデコードを確認しました。

- 動画メタデータ：547秒。M4A：546.97秒。差：−0.03秒。
- 8,852,867バイト、9区間。取得0.594秒（14.901 MB/s）。
- 確認後、一時音声を削除。ログはURLの署名を含みません。

この結果はPC上の実測です。iPhone上のYouTubeKitの取得結果、ユーザー端末の実際の通知、広告時の振る舞いは未計測です。

Swift構文とプロジェクト・リソースの整合性を確認。読み込み・別動画・未確定時間・一時停止の誤判定、不一致の待機と本編への自動復帰の回帰テストを追加しました。確認表示を閉じても次の通知で繰り返し表示されないことも検証。M4Aを実際に解析・保存・削除する既存テストにも12秒の長さの照合を追加しています。

[GitHub Actions 37416419472](https://github.com/tomikan1208-code/iphone-haptic-lab/actions/runs/37416419472)が成功。対象コードは `c73b5a984afb57e42b267026d55f6f3bcd9531bf`、macOS 15.7.9・Xcode 16.4で実機arm64 IPAを生成しました。

- iPhone SE第3世代・iOS 26.2シミュレーター：単体56件、画面操作5件、合計61件成功。失敗・スキップ0件。
- 今回の長さ判定の回帰テスト5件と、実M4Aの12秒解析・保存・一時音声削除・再起動後読み込みのテストが成功。
