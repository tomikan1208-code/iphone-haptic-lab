このページは修正前の監査記録。後続のコード改善と全曲再解析は [改善後の検証](SERENADE-IMPROVED.md) に記録する。

## 136 BPMになった理由

前回の `arrangement-3.2` が出した136 BPMは、All-In-Oneの後処理による値である。インストールした `allin1_infer/postprocessing/tempo.py` を確認すると、隣り合う拍の間隔ごとに `60 / interval` を計算し、整数へ丸めた後、その最頻値を採用していた。

137 BPMの四分音符は約0.437956秒。10 ms刻みの拍時刻では、0.44秒の間隔が多数を占める。その一つ一つから計算すると136.36 BPMになり、整数化で136となる。今回のAll-In-Oneでは、この整数136の票が331個だった。短い間隔を先に丸める方式には、この偏りがある。

保存された拍時刻を複数拍にわたって集計すると次の値になる。

| 集計 | All-In-One | Beat This |
| --- | ---: | ---: |
| 0.35秒超・0.55秒未満の拍間隔を平均してからBPMへ変換 | 136.9968 | 137.1120 |
| 10–30秒：拍番号と時刻の直線近似 | 137.0010 | 137.1703 |
| 90–115秒：同上 | 136.9842 | 137.0038 |
| 190–211秒：同上 | 137.0466 | 136.9843 |

平均する間隔の範囲は137 BPM付近の通常拍を調べるための監査条件で、汎用テンポ推定の実装ではない。直線近似は窓内の連番拍番号 `i` に対して `t_i = a + b*i` を最小二乗で当てはめ、`BPM = 60/b` とした。JSONには不安定な窓も含む6区間の結果と残差を残した。余分な拍のある区間では約140–144 BPMになるが、その値だけを本当の加速と解釈できない。

136と137の差は約0.73%。仮に136の固定格子を生成すれば、四分音符32拍で137の格子から約103 msずれる。ただし現在の編曲は実際の検出拍時刻を使用するため、表示BPMの136だけでこの累積ずれが発生するわけではない。

## 拍子の誤検出は別の問題

出力126区間の拍数は4拍112、5拍3、6拍3、2拍7、3拍1だった。これらはアルゴリズムが作った区間数であり、原曲の正解小節数ではない。

次の4区間では、約4拍分の時間に余分な拍が入っている。All-In-Oneは通常の約0.44秒間隔で4拍を出す一方、採用されたBeat Thisに約0.10–0.12秒間隔の追加イベントがある。これは5/4・6/4の根拠として扱えない。

| 区間（MV秒） | 出力拍数 | 区間長÷137 BPMの四分音符長 | 出力の信頼フラグ |
| --- | ---: | ---: | --- |
| 44.14–45.90 | 5 | 4.019 | true |
| 45.90–47.66 | 5 | 4.019 | true |
| 162.38–164.16 | 5 | 4.064 | true |
| 164.16–165.90 | 6 | 3.973 | true |

例えば44.14–45.90秒のBeat This出力は `44.14, 44.58, 45.02, 45.12, 45.48`。通常拍の45.02秒の直後に45.12秒を余分に数えている。追加イベントが実音の16分音符に対応していても、それを四分音符の拍として数えるのは誤りになる。

現在の [rhythm_grid](../../pc-server/haptic_arrangement.py) のモデル一致評価は、片方の拍からもう片方の最近傍を探す方向の比率を使う。この方法では、もう片方に追加されたイベントを十分に減点できない。局所的な信頼判定も半数以上の一致で通るため、上の5拍・6拍区間が `reliable: true` になった。**前回の一致率96.53%は正答率ではなく、これらの誤検出がないことを保証しない。**

一方、58秒付近の6拍区間、178–184秒の2拍区間などは、真の拍子変更・小節頭の欠落・細分化を区別する手動確認が必要になる。公開譜に拍子変更があるため、すべての非4拍区間を4拍へ置き換える修正は不適切である。

## サビ・編曲への影響

前回のAIは51.20–88.86秒、116.89–130.91秒、160.69–214.13秒をサビのまとまりとして検出した。この秒数は正解注釈ではない。採譜資料のCサビとDメロを同じ `chorus` にまとめている可能性があり、サビ後半の別フレーズを区別する検証が必要になる。

この曲に振動を編曲するなら、テンポだけでなく、跳ねた裏拍とフレーズの区切りを保持する必要がある。作者のコメントを踏まえると、静かな持続感と軽いアタックを基調にし、サビでも強度だけで盛り上げない設計が考えられる。これは調査を踏まえた編曲上の提案で、唯一の正解ではない。

## 改善する順序

1. テンポを短い間隔の整数最頻値から、複数拍の周期・位相を使う推定へ変更する。実際のテンポ変化を保持し、137を曲ごとに直書きしない。
2. 拍の照合を一対一にし、両方向の一致と余分な拍を評価する。モデル間の整合性と、人が付けた正解に対する精度を別に報告する。
3. 局所周期、小節長、拍の連続性を合わせて信頼度を判定する。重複を除く際も、細分音符のオンセットは表現用に残し、本当の拍子変更は保持する。
4. 拍内オンセットからスウィング比率を推定し、四分音符の拍格子と16分音符の跳ねを分離する。
5. 同じMVに人手の拍・小節頭・拍子変更・構造境界を付け、重複拍と検出漏れ、境界誤差を評価する。オンライン楽曲DBや別バージョンの時間をそのまま正解にしない。

今回の変更は参照情報と監査記録の追加。既存のモデル結果、過去のmetrics、解析処理は書き換えていない。
