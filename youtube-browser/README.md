# Reson Web 0.2 — YouTubeと振動

YouTube.comを直接再生する別のiPhoneアプリ。YouTubeのログイン・履歴・再生リストを使いながら、保存した振動を動画の再生位置へ同期する。

| アプリ | アプリ識別子 |
| --- | --- |
| Reson | com.tomikan1208.hapticlab |
| Reson Web | com.tomikan1208.resonweb |

Resonとは共存する。Resonの曲・解析・振動設定は変更しない。Reson Webの0.1からは同じ識別子のまま更新し、永続的なWebサイト保存領域を維持する。更新時は0.1と同じ署名方法を使い、アプリを削除せずに上書きする。

## 振動を使う

1. YouTubeで動画を開く。画面下の「作成」を押す。
2. iPhoneで精密解析、またはPCでAI編曲を選び、作成を開始する。PCは「解析方法・PCサーバー」で接続する。Resonと同じPCサーバー・接続キーを利用できる。
3. 作成が完了すると、この動画の再生・一時停止・早送り・再生速度に振動が同期する。保存後は振動の再解析やPCへの接続は不要。
4. 「調整」で全体の強さ、持続振動、瞬間振動、瞬間の鋭さ、密度、同期補正を調整する。「打音をくっきり」で全体80%・持続25%・瞬間100%・鋭さ90%・密度100%にする。

広告中、読み込み中、動画を切り替えている間、バックグラウンドでは振動を待機する。未作成の動画では勝手に解析を始めない。振動をオフにしてもYouTubeの再生は継続する。画面のバーをたたんでも同期は続く。

振動はこのアプリ内に保存する。「…」→「保存した振動」で動画を開き直せる。グローバルと動画ごとの設定、解析の作り直し、保存済み解析の切り替え・選択削除に対応する。Resonの保存データを自動で移行する機能は含まない。

1曲20分・512 MBまで。ライブ配信は解析対象外。音声の取得に失敗した場合は、同じ音源のファイル・音声URLを指定できる。ブラウザのCookieやログイン情報を解析サービスへ送信しない。

## YouTubeの画面とログイン

外側は黒とグリーンのResonの配色、検索／履歴／再生リストの3タブ。中央にはYouTubeの実ページを表示する。サイト内部のヘッダー、動画操作、広告、コメント、再生リストはYouTube側で操作する。動画の全画面機能もYouTubeの操作を使う。

0.1.0でのログインとYouTube側の履歴保存は、ユーザーが実機で確認済み（2026-10-08）。本バージョンのビルド検証はユーザーのアカウントにアクセスしない。Safariのログイン状態とは別の保存領域を使う。

動画の同期にはHTMLの動画要素の再生状態を読み取る。独立したスクリプト領域で、YouTubeのメインページだけを観測する。Googleの認証ページでは観測処理を開始せず、Cookieの削除やサイトの操作画面の書き換えは行わない。[Appleのスクリプト領域の説明](https://developer.apple.com/documentation/webkit/wkcontentworld)。YouTube側のページ構造が変わった場合は同期処理の調整が必要になることがある。

## ビルドと検証

iOS 16以降。Macで `bash scripts/build-and-test.sh` を実行する。GitHub Actionsの `Build Reson Web` でもIPAを生成する。配布IPAは未署名なので、これまでと同じ手順で署名してインストールする。

UI検証には選択したXcodeのSDKと同じバージョンのiOSシミュレーターを使う。CIの標準はXcode 26.2とiOS 26.2。手動実行ではXcode 16.4とiOS 18.5も選べる。ビルド環境と検証端末を `BUILD-INFO.json` に記録する。

Web再生の観測処理は6件のテストで広告・停止・シーク・動画の切り替え・認証ページ除外を確認する。ネイティブテストは保存・解析・設定・同期の停止条件を確認する。UIテストではオフラインの実際のHTMLメディア時計を使い、振動の作成、持続／瞬間の独立調整、広告待機、再起動後の保存を確認する。

CIでの検証はGoogleログイン・YouTubeの履歴書き込み・物理的な振動の感触の実機確認を含まない。結果と0.1でのユーザー確認の範囲を `BUILD-INFO.json` に記録する。
